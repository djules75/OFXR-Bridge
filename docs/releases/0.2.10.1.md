# OFXR Bridge v0.2.10.1 (V412)

Built on
[tig3rmast3r's v0.2.1](https://github.com/tig3rmast3r/OFXR-Bridge/releases).
This release is about **video memory**: OFXR now needs noticeably less of
it, in every game.

## What's new

### Less VRAM, across the board

| Game type | Saving | Measured |
|---|---|---|
| **D3D12 and D3D11** | about **15 to 30% less**, depending on the game | MSFS 2024 on SteamVR, 3X: 3.6 → 3.1 GB |
| **Vulkan** (No Man's Sky…) | about **half** | No Man's Sky on SteamVR: 20.2 → 16.9 GB for the whole game |
| **Pimax OpenXR** | about **35% less** (see below) | MSFS 2024, 3X: 7.0 → 4.6 GB |

- **Pimax OpenXR still uses more VRAM than SteamVR.** Pimax Play's OpenXR
  runtime keeps an extra copy of every image it is handed, until the game
  closes. This release halves that cost, but OFXR still needs about **1.5
  times** more VRAM on Pimax OpenXR than on SteamVR. We have reported it to
  Pimax; nothing more can be done on OFXR's side.

  **If you have a Pimax headset and run short of VRAM, use SteamVR with
  [sboys3's native SteamVR driver](https://store.pimax.com/blogs/blogs/sboys3-native-steamvr-driver-setup-guide)**
  and make SteamVR the active OpenXR runtime (SteamVR → Settings → OpenXR).
  This matters most in MSFS 2024.
- 2X, 2X with **Prefer FPS over latency** and **3X Frame Gen** now all use
  the same amount of VRAM.
- **Vulkan games** now take the same path as D3D11 games, which is what
  halves their VRAM. They also get the same frame pacing as D3D12 games.
- **OFXR no longer loads in Pimax Home.** Pimax Home takes over the headset
  every time a game leaves VR, and OFXR used to hold its memory there the
  whole time, on top of the game's.

The [troubleshooting guide](../TROUBLESHOOTING.md#how-much-vram-ofxr-uses)
has an updated table of how much VRAM OFXR needs at your resolution.

### Flight logs record VRAM

The flight recorder now writes how much VRAM OFXR uses and the resolution
your game really renders at. If you report a VRAM problem, a flight log now
answers most of our questions on its own.

## Known issues

- **Check your real per-eye resolution.** SteamVR's global resolution and a
  per-game resolution **multiply**: 200% global with 200% for the game gives
  four times the pixels, and OFXR's memory grows with them. The
  troubleshooting guide explains how to read the real value from a flight
  log.
- **SteamVR: turn off Motion Smoothing and "fixed frame rate at half" for
  the game** in SteamVR's per-application video settings. They fight with
  OFXR's own pacing.
- **No FPS overlay in Vulkan games.**

## Installing

Unzip anywhere and run `OFXRBridgeTray.exe`. It arms the bridge by itself.
Keep `OFXRBridgeTray.exe` and the `ofxr` folder together; it holds the OpenXR
layer, its settings and the Vulkan layer. If an earlier version is armed,
disarm it and close its tray first.

Please report results, working or not, on this fork's
[GitHub Issues](../../issues), with an OFXR flight log where you can. To
record one, enable **Bridge flight recorder** in the tray, reproduce the
problem, then use **Open bridge logs**. Logs are written under
`%LOCALAPPDATA%\OFXR Bridge\RuntimeLayer\v412\`. Read the
[troubleshooting guide](../TROUBLESHOOTING.md) first: most problems are
solved there in a few minutes.
